# SnapContext 프로젝트 마무리 기록 (2026-10-11)

> 결정: **선택지 E — 이 프로젝트를 중단하고 다른 아이템으로 간다.** 이 문서는 무엇을 만들었고, 무엇이 잘못됐고, 다음 아이템에 무엇을 가져갈지 적는다.

## 1. 무엇이 만들어졌나 (기술적으로는 동작하는 제품)

- Windows 캡처 도구: 전역 단축키 → 영역 선택(숫자키로 프리셋 선택) → 설명 띠를 합성한 이미지 한 장을 클립보드에 한 번에 복사 → `Ctrl+V`.
- 프리셋 저장소(손상 복구 포함), 편집 창, 트레이 아이콘, 클립보드 히스토리 제외 플래그.
- MSIX 패키징까지 검증: 자체 포함 게시, `.msix` 76MB 생성, 설치해서 전역 단축키·패키지 정체성 확인.
- 자동 시험 157개(저장소 밖), ChatGPT에서 합성 이미지 비교 시험 6번 통과.
- 수익성 가상 검증, 배포 경로 조사, 스토어 정책 조사.

## 2. 왜 중단하나

1. **가치가 약하다.** 고정 프리셋 문장은 LLM이 이미 하는 일(이미지를 보고 스스로 판단)에 거의 정보를 더하지 못한다. 합성 이미지와 글자 입력이 같은 결과였다는 시험은 "타이핑 몇 초 절약"이 전부라는 뜻이다.
2. **플랫폼이 같은 기능을 기본 제공하기 시작했다.** ChatGPT Appshots(Windows, 2026-09-11, 이미지 + 앱이 노출하는 글자), Gemini Windows 앱(2026-09-10), Windows Click to Do.
3. **수익 구조가 안 맞는다.** 화면을 안 보고 쓰는 도구라 광고 노출이 거의 없어 월 3만 원에 월 활성 사용자 약 3만 명이 필요했다. 직접 배포 서명 비용은 목표 수익과 같은 규모였다.
4. **제작자 본인이 쓰지 않을 것 같다고 평가했다.**

## 3. 무엇을 잘못했나 (다음에 반복하지 않을 것)

| 실수 | 결과 |
|---|---|
| **수요를 검증하지 않고 만들었다.** 기술 가능성과 규칙 검증에 시간을 썼고 "누가 이걸 왜 설치하는가"에는 답하지 않았다 | 출시 직전 단계에서야 가치 문제가 드러났다 |
| 플랫폼 리스크를 문서에 적어 놓고 **최신 현황을 확인하지 않았다** | Appshots 출시를 뒤늦게 알았다 |
| 기능을 계속 얹었다(글자 인식, AI 3개 버전, 설명 복사) | 대부분 삭제했고 시간만 들었다 |
| 수익 모델을 검증하기 전에 개발했다 | 광고 수익 구조가 안 맞는다는 것을 개발 후반에 계산했다 |
| 수동 시험을 사용자에게 많이 시켰다 | 사용자 부담이 컸다 |

## 4. 다음 아이템에 가져갈 규칙

1. **코드를 쓰기 전에 수요 검증부터.** 랜딩 페이지, 사전 등록, 인터뷰 5~10명, 통과 기준을 미리 정한다.
2. **경쟁과 플랫폼 현황을 먼저 조사한다.** 같은 기능을 무료로 제공하는 큰 플랫폼이 있는지 확인한다.
3. **수익 모델의 숫자를 먼저 계산한다.** 필요한 사용자 수가 현실적인지, 광고를 보여 줄 지면이 구조적으로 있는지.
4. **가장 작은 시험(스모크 테스트)으로 시작한다.** 만들기 전에 팔 수 있는지부터.
5. 기능 추가는 "사용자 확보나 수익에 도움이 되는가"를 통과해야 한다.

## 5. 재사용할 수 있는 것

- WPF 전역 단축키(`HotkeyManager`), 클립보드 쓰기와 히스토리 제외(`ClipboardHelper`), 트레이 아이콘(`TrayIcon`), 손상에 강한 설정 저장소(`PresetStore`).
- MSIX 패키징 파이프라인(`packaging/`): 스토어 무료 등록과 Microsoft 서명으로 인증서 비용 0원 경로를 확인했다.
- 수익성 모델(`docs/RELEASE_AND_REVENUE_PLAN.md`): 월 활성 사용자 × 노출 × 단가 계산틀, 지급 기준, 비용 비교.
- 시험 방법: 창을 띄우지 않는 WPF 시험, 키 입력 전 안전 확인, 실제 앱 end-to-end 점검 스크립트.
