## 2. 가상 수익성 검증

### 2-1. 가정 (전부 검증되지 않음)

- 환율 1달러 = 1,400원.
- 1,000회 노출당 수익(eCPM): 낮음 500원 / 기준 1,000원 / 높음 1,500원 (이전 기록의 가정치. 애드핏의 실제 값은 찾지 못했다. 참고로 네이버 애드포스트는 조회당 약 0.8~1.2원 정도로 어림하는 글이 있다.)
- 월 활성 사용자(MAU) 1명이 만드는 광고 노출 수:
  - **웹 링크만**(앱에서 웹페이지로 이동): 낮음 0.3 / 기준 0.9 / 높음 2.0회
  - **앱 안 창에 광고**(설정·히스토리 창): 낮음 3 / 기준 8 / 높음 15회
- 이 앱은 "화면을 보지 않고 쓰는" 도구라서 광고가 보일 기회 자체가 적다(규칙 A-4가 캡처 직후 흐름에 광고를 금지).

### 2-2. 월 3만 원을 만들려면 필요한 월 활성 사용자

| 광고 방식 | 최선 | 기준 | 최악 |
|---|---|---|---|
| 웹 링크만 | 약 10,000명 | **약 33,000명** | 약 200,000명 |
| 앱 안 창에 광고 | 약 1,300명 | **약 3,800명** | 약 20,000명 |

월 5만 원이면 위 숫자의 약 1.7배입니다.

### 2-3. 사용자 수별 월 수익 (노출·eCPM 모두 기준값)

| MAU | 웹 링크만 | 앱 안 광고 |
|---|---|---|
| 100 | 90원 | 800원 |
| 300 | 270원 | 2,400원 |
| 1,000 | 900원 | 8,000원 |
| 3,000 | 2,700원 | 24,000원 |
| 10,000 | 9,000원 | 80,000원 |

### 2-4. 비용과 수령

- 직접 배포용 OV 인증서: 연 약 16만~62만 원 = **월 약 1.4만~5.1만 원**. 목표 수익(월 3~5만 원)과 같은 규모라서, **서명 비용이 수익을 거의 다 먹는다.**
- 월 3만 원 기준 지급 기준 도달: 애드핏 약 1.7개월, 애드센스 약 4.7개월 적립 후에야 받는다.
- 스토어 배포(MSIX)는 인증서 비용이 0원이다.

### 2-5. 비교: 광고 대신 유료 옵션 (1회 결제 3,000원, 스토어 수수료 전)

| MAU | 전환율 1% | 전환율 2% |
|---|---|---|
| 300 | 9,000원 | 18,000원 |
| 1,000 | 30,000원 | 60,000원 |
| 3,000 | 90,000원 | 180,000원 |

1회성 매출이라 월 수익과 직접 비교할 수는 없지만, 사용자 1인당 가치는 광고(월 수 원)보다 결제가 훨씬 크다.

### 2-6. 판정

1. **현재 설계(웹 링크 + 광고)로 월 3~5만 원은 사용자 약 3만 명 이상이 있어야 가능하다.** 이전 기록의 "2천~1만 명"은 앱 안 창에 광고를 충분히 보이는 것을 전제한 낙관적인 값이었다.
2. **앱 안 창에 광고를 넣으면 필요 사용자가 약 10분의 1로 줄지만**, 쓸 수 있는 광고망이 없다(애드센스는 데스크톱 앱 금지, 애드핏은 웹/모바일 앱만, 앱용 SDK는 갱신이 끊김).
3. 병목은 광고 기술이 아니라 **사용자 확보**다. 사용자 확보 경로(스토어 검색, 블로그·커뮤니티 홍보)는 아직 계획이 없고, 이 제품 범주의 실제 확보 속도에 대한 근거도 없다.
4. 따라서 **지금 기능을 더 만들어도 수익 가능성은 늘지 않는다.** 먼저 배포하고 실제 사용자 수를 측정해서 위 표에 대입해야 한다.

## 3. 배포 경로 비교

| | A. 스토어(MSIX) | B. 직접 배포(서명한 EXE) |
|---|---|---|
| 서명 비용 | 0원(Microsoft가 서명) | 연 약 16만~62만 원 |
| 경고 화면 | 스토어 설치는 경고 없음 | 서명해도 평판이 쌓이기 전까지 경고 가능 |
| 발견 경로 | 스토어 검색(사용자 확보에 유리) | 직접 홍보만 |
| 자동 업데이트 | 스토어가 해 줌 | 직접 구현 |
| 미확인 위험 | 전역 단축키, 트레이, 화면 캡처, 클립보드가 MSIX에서 모두 동작하는지(전체 권한 앱이면 가능한 것으로 알려졌으나 **이 프로젝트에서 확인하지 못함**), 광고 정책, 심사 기간 | 서명 비용과 인증서 하드웨어 |
| 규칙 B-8(서명 없이 배포 금지) | 스토어 서명으로 충족 | 인증서 구매 필요 |

**권장: A(스토어)를 먼저 시도한다.** 비용이 0원이고 사용자 확보 경로까지 얻는다. 먼저 MSIX 환경에서 핵심 기능이 동작하는지 작은 시험(PoC)으로 확인한다. OCR을 삭제했기 때문에 MSIX 전환의 큰 걸림돌이 하나 사라졌다.

## 6. 이 분석의 한계

- 사용자 확보 속도, 광고 단가(eCPM), 링크 클릭률은 **전부 가정이며 실측이 없다.** 위 표는 방향을 보는 용도다.
- 스토어 정책과 심사 조건은 실제 제출 과정에서 달라질 수 있다.
- 서명 인증서 가격은 판매 사이트 정보다.

## 7. 사용자 결정 (2026-10-09)

1. **수익 모델: 광고 + 유료 후원 병행.** 후원 금액은 100원이라도 괜찮다.
2. **배포 경로: 스토어(MSIX) 우선.** 다음 작업은 MSIX 환경 확인이며, 그때까지 새 기능 추가는 멈춘다.
3. **중단/계속 기준: 5절의 숫자를 그대로 사용한다**(출시 4주 설치 300 이상, 8주 월 활성 사용자 100 이상, 12주 실측값 대입).

## 8. 후원에 대한 추가 조사 (결정에 영향, 일부 미확정)

- 스토어 정책 10.8.2(2021년 Microsoft Q&A 인용 기준): **자발적 후원은 Microsoft 결제 요청 API 또는 안전한 제3자 결제 API로 받아야 하고, 후원자에게 기능 추가나 광고 제거 같은 보상을 주면 스토어 인앱 구매 API를 써야 한다.** 앱에서 외부 후원 사이트로 보내는 링크가 허용되는지는 **확인하지 못했다.**
- 스토어 인앱 구매의 **최저 가격(원화)은 확인하지 못했다.** "100원"이 가능한지는 Partner Center에서 상품을 만들 때 확인해야 한다(일반적으로 최저 가격 단계가 있어 100원은 어려울 가능성이 있다. 추정).
- 정책 10.8.1(2025-09)은 스토어 밖 시장에서 인앱 디지털 재화를 현실 가치와 교환하는 것을 금지하도록 바뀌었다.
- 안전한 설계(제안): ① **웹사이트**에 후원 링크를 둔다(앱 밖이므로 앱 심사와 무관). ② 앱 안에서는 후원 링크를 넣기 전에 Partner Center 지원에 확인하거나, 스토어 인앱 구매로 "후원" 상품(보상 없음 또는 감사 표시)을 만든다. ③ 후원자에게 기능을 주려면 반드시 스토어 인앱 구매를 쓴다.
- 이 설계는 R3(웹사이트)과 R4(스토어 제출) 단계에서 확정한다.

## 9. MSIX 환경 확인 계획 (R1)

확인 대상: MSIX(전체 권한 데스크톱 앱) 환경에서 **전역 단축키(RegisterHotKey), 트레이 아이콘, 화면 캡처(GDI), 클립보드(제외 플래그 포함), 프리셋 파일 저장(AppData), 시작 시 자동 실행(startupTask)**이 동작하는지. 전체 권한 앱은 일반 Win32 프로세스로 실행되므로 대부분 동작할 가능성이 높지만 **이 프로젝트에서 확인한 적은 없다.**

| 단계 | 내용 | 필요한 것 |
|---|---|---|
| 1 | 매니페스트와 아이콘 에셋 작성, 빌드 스크립트 작성 | 없음(완료) |
| 2 | 자체 포함(self-contained) 게시: .NET 런타임 패키지 2개 | nuget.org에서 약 69MB 다운로드(Microsoft.NETCore.App.Runtime.win-x64 34MB, Microsoft.WindowsDesktop.App.Runtime.win-x64 35MB, 버전 8.0.31) |
| 3 | 패키지 검증과 .msix 만들기: makeappx | nuget.org에서 약 22MB 다운로드(Microsoft.Windows.SDK.BuildTools 10.0.28000.2705) |
| 4 | 실제 설치와 실행 확인 | **개발자 모드 켜기(사용자가 직접, 설정 변경이라 제가 할 수 없음)** — 서명 없이 등록해서 시험할 수 있음 |
| 5 | 스토어 예약 이름과 게시자 식별자로 교체 | 사용자가 스토어 개발자 등록(신분증+셀피, 사용자가 직접) |
