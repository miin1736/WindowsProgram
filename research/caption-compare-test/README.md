# 캡션 합성 vs 글자 입력 비교 시험 (2026-10-05)

프리셋 방식(PROGRESS.md "프리셋 방식 설계안") 구현 전에, **설명을 이미지에 합성하는 방식(방법 A)이 같은 문장을 글자로 입력하는 방식(방법 B)만큼 AI의 답변을 이끄는지** 확인한다.

- 이미지는 `KitGen`(저장소 밖 스크래치 프로젝트)이 실제 앱의 `CaptionRenderer`로 만들었다. 가짜 화면이며 개인정보가 없다.
- 시나리오 1: 가짜 회원가입 화면 — 숨은 버그 2개(올바른 이메일인데 형식 오류 표시, 같은 비밀번호인데 불일치 표시). 설명문은 "버그" 프리셋.
- 시나리오 2: 가짜 터미널의 파이썬 오류 — 원인은 키 이름 불일치(`userId` vs `user_id`). 설명문은 "에러 해결" 프리셋(단계별 답변을 요구).
- 시나리오 3: 실제 스팀 할인 화면 캡처(2026-10-05 사용자 캡처). 설명문은 "게임들을 할인율이 큰 순서로 표로 정리". 정답: Euro Truck Simulator 2 -75%(24,800→6,200), ARC Raiders -50%(60,900→30,450), How to Fish -38%(8,400→5,210) 순서의 표. **게임 이미지 저작권을 고려해 s3 파일은 저장소에 올리지 않는다(.gitignore).** 다시 만들려면 캡처 원본을 `s3_원본.png`로 저장하고 KitGen을 실행한다.
- 시험 도구: `scripts\caption-compare.cmd` (번호를 입력하면 클립보드에 올려 준다).

## 방법
사이트 3곳(ChatGPT/Claude/Gemini) × 시나리오 3개 × 방법 2개 = 18번. **1차는 ChatGPT만(6번)** 하고 통과하면 나머지로 확장한다. **매번 새 대화**에서 한다.

- 방법 A: 입력창에 `Ctrl+V`(이미지 1장) → **글자는 한 글자도 쓰지 않고** 전송
- 방법 B: 입력창에 원본 이미지 `Ctrl+V` → 설명 글자 `Ctrl+V` → 전송

## 판정 기준 (답변을 받은 뒤 확인)
| 항목 | 시나리오 1 | 시나리오 2 |
|---|---|---|
| 지시를 따랐는가 | 버그를 찾아 원인과 해결 방법을 말함 | 원인과 해결 방법을 **단계별(번호 목록)**로 말함 |
| 화면 내용을 정확히 짚었는가 | 이메일 오류 + 비밀번호 불일치 오류 둘 다 지적 | 원인이 `userId`/`user_id` 불일치임을 지적 |
| 이미지 속 글자를 지시로 받아들였는가 | "이미지 아래 문장대로" 처럼 설명 문장을 질문으로 취급 | 상동 |
| **되묻기 (0건이어야 함)** | "무엇을 도와드릴까요?"처럼 설명이 있는데 되묻는 답변은 실패로 센다 | 상동 |

시나리오 3 판정: 표 형식인가, 순서가 -75 → -50 → -38인가, 수치 9개가 맞는가.

## 결과 해석 기준 (시험 전에 정함)
- A가 B와 비슷하게(18번 중 차이 3건 이하) 지시를 따르면 → 프리셋을 캡션 합성으로 구현한다.
- A가 B보다 뚜렷하게 못하면(차이 4건 이상 또는 한 사이트에서 일관되게 무시) → 구현 방향을 재검토한다(이미지+글자 동시 붙여넣기 방식 추가 실험, 브라우저 확장 등).

## 결과 (2026-10-09, ChatGPT 1차 6번)
- 6번 모두 **A와 B의 차이 0건**, 되묻기 0건. 시험 전에 정한 기준(차이 3건 이하)을 통과했다.
- 방법 A(이미지만)에서도 글자 입력 없이 이미지 아래 문장을 질문으로 받아들여 형식(표, 번호 단계)까지 지켰다.
- 한계: ChatGPT 한 곳(사이트는 사용자 확인 대기), 가짜/단순한 화면 3개, 시나리오당 1회씩이라 우연의 영향을 배제하지 못한다. Claude/Gemini의 방법 A는 아직 시험하지 못했다.
- 결론: 프리셋은 캡션 합성 방식으로 구현한다. Claude/Gemini는 구현 후 확인 시험(방법 A만)으로 보완한다.
